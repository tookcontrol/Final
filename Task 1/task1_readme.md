# Task 1: Encrypted Messaging App Prototype - Explanation

This system demonstrates a hybrid encryption approach, combining the efficiency of symmetric encryption (AES) for the message content with the security of asymmetric encryption (RSA) for key exchange.

## Encryption Flow (User B)

1.  **Message Creation**: User B writes the secret message to `message.txt`.
2.  **AES Key Generation**: A cryptographically secure random 256-bit key is generated for AES encryption. This key will only be used for this specific message (ephemeral key).
3.  **AES Encryption**:
    *   The content of `message.txt` is encrypted using AES-256 in GCM (Galois/Counter Mode).
    *   GCM is an authenticated encryption mode, meaning it provides both confidentiality (encryption) and integrity/authenticity (via an authentication tag).
    *   A random nonce (similar to an IV) is generated and used in the encryption.
    *   The output (`encrypted_message.bin`) contains the nonce, the authentication tag, and the ciphertext.
4.  **RSA Encryption (AES Key)**:
    *   To securely send the AES key to User A, User B encrypts the *AES key* using User A's *public RSA key*.
    *   OAEP padding is used with RSA encryption, which is the recommended standard for security.
    *   The encrypted AES key is saved to `aes_key_encrypted.bin`.
5.  **Transmission**: User B sends `encrypted_message.bin` and `aes_key_encrypted.bin` to User A.

## Decryption Flow (User A)

1.  **RSA Decryption (AES Key)**:
    *   User A receives the files.
    *   User A uses their *private RSA key* to decrypt `aes_key_encrypted.bin`. This recovers the original AES key generated by User B. OAEP padding must be specified during decryption as well.
2.  **AES Decryption**:
    *   User A reads `encrypted_message.bin`.
    *   The nonce and authentication tag are extracted from the beginning of the file.
    *   The rest of the file (the ciphertext) is decrypted using the recovered AES key and the extracted nonce, specifying AES-GCM mode.
    *   During the `finalize()` step of decryption, the GCM mode automatically verifies the authentication tag. If the tag is valid (meaning the ciphertext or nonce wasn't tampered with), decryption succeeds. If not, an exception is raised.
    *   The resulting plaintext is saved to `decrypted_message.txt`.

## Why Hybrid Encryption?

*   **Efficiency**: Symmetric algorithms like AES are significantly faster than asymmetric algorithms like RSA, making them suitable for encrypting large amounts of data (the message).
*   **Key Management**: Asymmetric encryption solves the problem of securely sharing the symmetric key. Encrypting the relatively small AES key with RSA is computationally feasible and allows secure key exchange without a pre-shared secret.
